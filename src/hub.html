# Instalação

  1. Crie um fork pessoal a partir deste repositório REPOSITÓRIO-HUB
  2. Clone o fork em seu ambiente local (git clone...)
  3. Após a clonagem, entre no diretório ./hubvendas-web e insira um remote correspondente ao repositório original
    git remote add hub https://github.com/beforeti/hubvendas-web.git
    OBS: Isso é para poder manter o teu local sincronizado com o repositório do HUB
  4. Duplique o arquivo .env.example e o renomeie para .env
  5. Configure seu .env para o ambiente de desenvolvimento:
    VUE_APP_ENV=development
  6. Agora é preciso configurar os acessos ao Localhost para simular o acesso de cada Provider
    - No terminal execute:
    sudo nano /etc/hosts
    - Edite o arquivo para que contenha os provedores:
    127.0.0.1 local.hubdevendas.localhost 127.0.0.1 local-alares.hubdevendas.localhost 127.0.0.1 local-neonfibra.hubdevendas.localhost
    - Salve as alterações
    // OBS: Esses são os links de acesso ao sistema

# Execução

Após a instalação, dentro do diretório do hub, execute
docker-compose up

# Propriedades genéricas do pedido

Propriedades que afetam todas as vendas, essas propriedades vêm direto no obj do list-sale
  1. has_captation
    • Exibe o campo `Tipo Captação` na tela de Iniciar Pedido - Atribuição de vendedor
    • list-sale: list-sale.has_captation
    • getter: 'Order/Core/getHasCaptation'
  2. has_ctos
    • Aplica a lógica de busca e seleção de CTOs no mapa de cobertura
    • list-sale: list-sale.has_ctos
    • getter: 'Order/Core/getHasCtos'
  3. can_move_pin
    • Faz com que o pin no mapa de cobertura possa ser movimentado
    • list-sale: list-sale.can_move_pin
    • getter: 'Order/Core/getCanMovePin'
  4. has_to_change_flow_by_role
    • Remove a rota ‘schedule’(agendamento) caso essa flag seja true e caso seja o flow de PAP (1)
    • list-sale: list-sale.has_to_change_flow_by_role
    • getter: 'Order/Core/getHasToChangeFlowByRole'

# Análise

Propriedade que afetam a tela análise, no list-sale vem no routes_props.analysis de um fluxo
  1. has_coverage
    • Define se a análise de cobertura será realizada
    • list-sale: list-sale.[fluxo].routes_props.analysis.has_coverage
    • getter: getters['Order/Core/getSelectedProviderSaleFlow'].routes_props.analysis.has_coverage
  2. has_credit
    • Define se a análise de crédito será realizada
    • list-sale: list-sale.[fluxo].routes_props.analysis.has_credit
    • getter: getters['Order/Core/getSelectedProviderSaleFlow'].routes_props.analysis.has_credit
  3. has_continue_jump_to_offers
    • Define se na tela de analise ao clicar continuar, se está flag for true e a cobertura tem o status ‘não realizado - not realized’ Ou o status da cobertura tem status ‘cidade sem mapeamento - city without mapping’
    • list-sale: list-sale.[fluxo].routes_props.analysis.has_coverage
    • getter: getters['Order/Core/getSelectedProviderSaleFlow'].routes_props.analysis.has_coverage
  4. has_continue_disapprove_analysis
    • Mostra o botão 'Continuar' mesmo com a análise reprovada
    • list-sale: list-sale.[fluxo].routes_props.analysis.has_continue_disapprove_analysis
    • getter: getters['Order/Core/getSelectedProviderSaleFlow'].routes_props.analysis.has_continue_disapprove_analysis
  5. has_handle_approved_analysis
    • Na análise de crédito individual, se isCreditApproved ou status = 4 (análise manual), exibe "Análises aprovadas" e o botão Continuar, ocultando Tentar novamente. Se houver flag de Crédito + Cobertura, além disso verifica se a Cobertura está aprovada.
    • list-sale: list-sale.[fluxo].routes_props.analysis.has_handle_approved_analysis
    • getter: getters['Order/Core/getSelectedProviderSaleFlow'].routes_props.analysis.has_handle_approved_analysis
  6. has_continue_with_credit_disapproved
    • Na tela de análise caso a analise de credito nao foi aprovada ou analise de credito nao aprovada e não tem cto esconde o botão de tentar novamente e exibe o botão de finalizar e continuar, além da mensagem de ‘Ops, a análise de crédito prévia não foi aprovada, porém, você poderá seguir com este pedido.’
    • list-sale: list-sale.[fluxo].routes_props.analysis.has_continue_with_credit_disapproved
    • getter: getters['Order/Core/getSelectedProviderSaleFlow'].routes_props.analysis.has_continue_with_credit_disapproved
  7. has_continue_with_credit_disapproved
    • Na tela de análise caso a analise de credito nao foi aprovada ou analise de credito nao aprovada e não tem cto esconde o botão de tentar novamente e exibe o botão de finalizar e continuar, além da mensagem de ‘Ops, a análise de crédito prévia não foi aprovada, porém, você poderá seguir com este pedido.’
    • list-sale: list-sale.[fluxo].routes_props.analysis.has_continue_with_credit_disapproved
    • getter: getters['Order/Core/getSelectedProviderSaleFlow'].routes_props.analysis.has_continue_with_credit_disapproved
  8. has_should_consider_bypass_coverage
    • Na tela de análise caso de erro em nos endpoints de analise credito e cobertura ou algum desses individualmente caso esta flag seja true executa uma função que leva em conta a flag shouldBypassCoverage e caso esta seja false exibe botão tentar novamente e a mensagem ‘A consulta de cobertura não foi realizada. Sua consulta será realizada posteriormente pela equipe de Backoffice’
    • list-sale: list-sale.[fluxo].routes_props.analysis.has_should_consider_bypass_coverage
    • getter: getters['Order/Core/getSelectedProviderSaleFlow'].routes_props.analysis.has_should_consider_bypass_coverage
